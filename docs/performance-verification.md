# 第六版：行走性能优化验证

## 四项实现

1. 普通画面统一由 RAF 绘制，删除 OrbitControls.change 的直接渲染。主题、尺寸、房门与屋顶变化只标记刷新；截图保留主动渲染与恢复。
2. 倒影在相机移动时仍限频：手机最多 12 Hz，桌面最多 18 Hz。波纹每帧更新；昼夜、尺寸、截图与镜头跳转强制刷新。法线阶段不更新倒影。
3. 动态阴影最多 30 Hz 更新。房门、屋顶显隐、主题、尺寸和截图触发立即更新；继续保留 2048 VSM 和软阴影配置。
4. 自适应画质按 high → ao-balanced → balanced → performance 降档。AO 先降低，之后才缩放像素比；低性能需连续两个有效一秒窗口、每次降档间隔至少三秒，健康帧持续八个窗口才恢复一级。忽略后台、超过 80 ms 的长间隔，截图和页面可见性改变清除采样。

## 证据与范围

- 修改前，在同一浏览器和道路点击路线下，8 个行走样本均记录到每个 RAF 两次 EffectComposer.render。修改后的 8 个行走样本均为一次；累计普通合成次数与主动画帧数同步增加。
- 连续模拟 60 Hz 的十秒刷新测试验证 12/18/30 Hz 上限；强制刷新重置时间间隔。移动相机的浏览器集成检查：120 次连续回调、2.9 ms 内只刷新一次；主题、截图强制刷新和 9 单位镜头跳转各立即增加一次倒影。
- `npm test`：5 项通过，覆盖限频、立即刷新、40 FPS 下的 AO 优先降档与下限、短尖峰/后台忽略、逐级恢复。
- 浏览器中实际实例化渲染管线，并输入受控的 25 ms 帧间隔，验证降档与 GPU 缓冲尺寸：balanced 档像素比 1.275、AO 比例 0.4、缓冲 497×1076；截图切到像素比 1、AO 比例 0.6、缓冲 946×2048；恢复后回到 1.275、0.4、497×1076，异常捕获为空。这是受控集成检查，不是实体设备 FPS 测量。
- 手机实际导出 PNG 为 946×2048、2,104,732 字节，解码成功，导出后恢复 390×844；当前参考文件为 `references/town-render-v6.png`。
- 进屋后第 5 栋屋顶隐藏、角色进入第一人称并停止；返回街道后九栋屋顶恢复。过程中 `rendersThisFrame=1`，异常捕获为空。
